# N&T Lab — وب‌سایت معرفی و پنل مدیریت (نسخه ۱.۴.۱)

وب‌سایت فارسی N&T Lab با صفحات اختصاصی نیما خالقا و دکتر بهروز طاهری، حالت روشن و تاریک، فرم ثبت درخواست و یک **پنل مدیریت واقعی** برای مدیریت محتوا و تیکت‌ها. رابط کاربری با فونت‌های Vazirmatn و Estedad طراحی شده است.

## اصلاح ضروری نسخه ۱.۴.۱

در نسخه ۱.۴.۰ خطای JavaScript مانع اجرای رندر پروژه‌ها و اعضای تیم می‌شد و ممکن بود بعضی بخش‌ها به‌خاطر انیمیشن نامرئی شوند. نسخه ۱.۴.۱ ترتیب فراخوانی را اصلاح کرده، محتوای پیش‌فرض را در صورت اختلال API حفظ می‌کند و جلوی مخفی شدن متن‌ها را در صورت خطای JavaScript می‌گیرد.

**برای به‌روزرسانی نسخه ۱.۴:** پیش از جابه‌جایی، از پوشه `data/` و فایل `.env` خود نسخه پشتیبان بگیرید. سپس فایل‌های برنامه را از نسخه جدید جایگزین کنید و **`data/` و `.env` را پاک یا بازنویسی نکنید**. نیازی به تنظیم مجدد پروژه‌ها و تیکت‌ها نیست. بعد از اجرای مجدد `npm start`، برای پاک‌کردن کش مرورگر `Ctrl+Shift+R` بزنید.

## راه‌اندازی در چند مرحله

**پیش‌نیاز:** Node.js نسخه ۲۰ یا بالاتر؛ این پروژه به نصب پکیج NPM نیاز ندارد.

1. پوشه فایل ZIP را استخراج کنید و وارد `nt-lab-site` شوید.
2. از `.env.example` یک نسخه به نام `.env` بسازید. اگر قبلاً `.env` دارید، آن را نگه دارید و فقط تنظیمات جدید مدیریت را به آن اضافه کنید.
3. یک رمز قوی و **جدید** برای پنل انتخاب کنید. کمینه ۱۲ کاراکتر است؛ ۲۰ کاراکتر یا بیشتر توصیه می‌شود.
4. `npm start` را اجرا کنید.
5. وب‌سایت: **http://localhost:3000/** و پنل: **http://localhost:3000/admin**.

تنظیمات پیشنهادی `.env` (این مقادیر فقط نمونه هستند؛ **حتماً `ADMIN_PASSWORD=change_me` را با رمز خصوصی ۲۰ کاراکتری یا قوی‌تر جایگزین کنید**. رمزها و توکن‌های واقعی را در چت یا مخزن کد منتشر نکنید):

```dotenv
PORT=3000
DATA_DIR=./data
ADMIN_PASSWORD=change_me
COOKIE_SECURE=false
TELEGRAM_BOT_TOKEN=your_fresh_telegram_bot_token
TELEGRAM_CHAT_IDS=123456789,987654321
```

- در محیط توسعه با `http://localhost` مقدار `COOKIE_SECURE=false` کافی است.
- **روی دامنه واقعی و پشت HTTPS** مقدار `COOKIE_SECURE=true` قرار دهید. با فعال کردن آن روی HTTP معمولی، کوکی ورود ذخیره نخواهد شد.
- فایروال و reverse proxy باید HTTPS را برقرار کنند. اطلاعات پنل را روی HTTP عمومی منتقل نکنید.
- **اگر توکن قبلی تلگرام را جایی منتشر کرده‌اید، از `@BotFather` با `/revoke` توکن جدید بگیرید.**
- بعد از تغییر فایل `.env`، سرور Node.js را متوقف و مجدداً راه‌اندازی کنید.

## پنل مدیریت چه کارهایی انجام می‌دهد؟

### درخواست‌های پروژه

- تمام **درخواست‌های جدیدی که پس از فعال‌سازی این نسخه از فرم سایت ارسال شوند**، در فضای ذخیره‌سازی خصوصی سرور ثبت می‌شوند، حتی اگر اتصال تلگرام در دسترس نباشد.
- پیام‌رسانی تلگرام همچنان فعال است و اگر تنظیم شده باشد، پس از ثبت محلی، اعلان برای مدیران فرستاده می‌شود.
- لیست تیکت‌ها دارای جست‌وجو، فیلتر وضعیت، جزئیات مشتری، بودجه، زمان‌بندی و وضعیت اعلان تلگرام است.
- وضعیت‌های تیکت: جدید، در حال بررسی، در حال انجام، انجام‌شده و ردشده.
- امکان ذخیره یادداشت داخلی برای هر درخواست و خروجی گرفتن CSV فراهم است.
- **تیکت‌های قدیمی که فقط در تلگرام هستند به‌طور خودکار به پنل وارد نمی‌شوند**؛ داده‌های تلگرام تاریخی فقط در خود تلگرام باقی می‌مانند مگر آنکه دستی مهاجرت داده شوند.

### محتوای سایت

- **متن‌های سایت:** بیش از ۳۰ فیلد برای عنوان‌ها، توضیحات خدمات، معرفی، مراحل همکاری و متن فوتر؛ بدون دست‌زدن به HTML قابل ویرایش هستند.
- **پروژه‌ها:** ایجاد، ویرایش و حذف کامل؛ عنوان، دسته‌بندی صاحب پروژه، توضیحات، برچسب‌ها، سال، نوع فعالیت، لینک منبع و تصویر.
- **اعضای تیم:** نام، عنوان تخصصی، معرفی کوتاه و کامل، مهارت‌ها، لینکدین، افتخارات، جزئیات و تصویر پروفایل هر نفر.
- **تصاویر اصلی:** بارگذاری لوگو و تصویر بخش اول سایت از تب «تصاویر اصلی و لوگو».
- **تصاویر:** PNG، JPG یا WebP با حداکثر حجم ۴ مگابایت. فایل‌های آپلودشده در سرور ذخیره شده و با آدرس `/media/…` نمایش داده می‌شوند؛ SVG و فایل‌های اجرایی برای امنیت ممنوع هستند.
- تغییرات با ذخیره‌شدن در پنل، در بارگذاری بعدی صفحات اصلی و اختصاصی هر نفر نمایش داده می‌شوند؛ نیازی به تغییر فایل کد نیست.

**فرمت ورود سوابق افراد در پنل:** هر رکورد در یک خط با جداکننده `|`:

```text
سال | عنوان | شرح | https://example.com/source
```

**فرمت جزئیات پروفایل:** هر بخش در یک خط؛ تعداد موارد دلخواه:

```text
عنوان بخش | مورد اول | مورد دوم | مورد سوم
```

## نگهداری و پشتیبان‌گیری (خیلی مهم)

این نسخه، اطلاعات را در فایل‌های محلی سرور ذخیره می‌کند:

```text
data/
  site-data.json        ← تیکت‌ها، متن‌ها، پروژه‌ها و پروفایل‌ها
  uploads/              ← فایل تصاویر آپلودشده
```

برای تهیه نسخه پشتیبان از داده‌ها و تصاویر، دستور `npm run backup` را در پوشه پروژه اجرا کنید. یک کپی تاریخ‌دار در `backups/` ساخته می‌شود. آن را در محل امن دیگری نیز نگه دارید.

این پوشه **جزئی از فایل ZIP اولیه نیست** و در اولین اجرای سرور به صورت خودکار ایجاد می‌شود. باید آن را پس از آپدیت حفظ کنید و به‌طور منظم از **کل پوشه `data`** روی محل امن نسخه پشتیبان بگیرید. اطلاعات مشتریان و راه‌های ارتباطی داخل آن شخصی و محرمانه هستند. فایل `.env` نیز خصوصی است.

- برای آپدیت از v1.3 به v1.4، `.env` فعلی را منتقل کنید و تنظیمات `ADMIN_PASSWORD` و `DATA_DIR` را اضافه کنید.
- بعد از شروع استفاده از پنل، هر وقت نسخه دیگری نصب کردید **پوشه `data` را همراه خود منتقل کنید**؛ بدون این پوشه تیکت‌ها، متن‌های ویرایش‌شده و تصاویر روی سرور جدید موجود نخواهند بود.
- برای استقرار، از **VPS یا هاستی با Node.js و دیسک دائمی** استفاده کنید. هاست استاتیک (مثلاً GitHub Pages) یا هاست با دیسک موقت برای ثبت دائمی تیکت و آپلود مناسب نیست.
- این ذخیره‌سازی برای **یک فرایند Node.js** طراحی شده است. برای بار کاری بالا یا چند instance هم‌زمان باید به پایگاه داده اشتراکی مثل PostgreSQL مهاجرت کرد.
- ورود فعلاً با یک رمز مدیر مشترک انجام می‌شود و نقش‌های چندکاربره یا سطح دسترسی جداگانه ندارد.
- نشست ورود پس از ۱۲ ساعت منقضی می‌شود و راه‌اندازی مجدد سرور هم نشست‌های فعال را از بین می‌برد.
- فایل‌های عکس حذف‌شده از یک پروژه به‌صورت خودکار از دیسک پاک نمی‌شوند تا احتمال حذف اشتباه داده کم شود؛ در صورت لزوم می‌توان فایل‌های بلااستفاده را با بررسی حذف کرد.

## ایمنی پنل

- تمام مسیرهای مدیریتی نیازمند نشست ورود معتبر هستند.
- رمز عبور سمت سرور با `scrypt` بررسی می‌شود و هرگز در محتوای عمومی یا کد JavaScript قرار نمی‌گیرد.
- نشست ورود با کوکی `HttpOnly` و `SameSite=Strict` نگه داشته می‌شود.
- درخواست‌های تغییردهنده به CSRF token نیاز دارند؛ تلاش ورود محدودسازی نرخ دارد.
- مسیر داده خصوصی از سرور وب قابل دانلود نیست. تنها تصاویر معتبر از `/media` در دسترس عموم هستند.
- لینک‌های منبع و نوع تصاویر ورودی از نظر اعتبار بررسی می‌شوند و محتوای متنی در مرورگر escape می‌شود.

برای سایت تجاری عمومی، HTTPS، نسخه پشتیبان خارج از سرور، رمز قوی، به‌روزرسانی سیستم و نظارت روی فضای دیسک لازم است.

## تست

```bash
npm test
npm run telegram:test
```

تست اول، کنترل‌های داخلی، مدیریت داده و اعتبارسنجی را بدون اتصال به اینترنت بررسی می‌کند. دستور دوم با اطلاعات تلگرام **خودتان** و شبکه واقعی، ارسال پیام آزمایشی انجام می‌دهد.

## ساختار فایل‌ها

```text
server.mjs                راه‌انداز HTTP، احراز هویت، API تیکت و آپلود
src/cms.mjs               مدل اطلاعات، اعتبارسنجی و ذخیره‌سازی اتمیک
src/tickets.mjs           اعتبارسنجی فرم و پیام تلگرام
public/admin.html         داشبورد و فرم ورود
public/admin.js           منطق مدیریت و ویرایش محتوا
public/admin.css          طراحی پنل واکنش‌گرا
public/cms-public.js      خواندن محتوای عمومی ذخیره‌شده از سرور
public/index.html         صفحه اصلی
public/team.html          صفحه معرفی عضو
public/main.js            نمایش پروژه‌ها و ثبت درخواست
public/profile.js         نمایش پروفایل و پروژه‌های عضو
public/content.js         داده اولیه پیش‌فرض (تنها برای ساخت اولین نسخه داده)
public/styles.css         طراحی سایت و فونت‌ها
scripts/                  ابزارهای عیب‌یابی تلگرام
```

**نکته:** پنل کد HTML/CSS سایت را برای طراحی مجدد ویرایش نمی‌کند؛ فیلدهای تعریف‌شده در پنل و تصاویر و پروژه‌های ثبت‌شده قابل مدیریت هستند. افزودن بخش‌های جدید یا تغییر ساختار اساسی صفحات همچنان نیاز به توسعه کد دارد.
